# PrintPilot · 产品一页纸

> 代号 PrintPilot，定位「3D 打印爆品工作台」· v0.1 · 2026-09-20

## 一句话

给 3D 打印个人卖家的一条**可度量的爆品流水线**：选品 → 出图 → 建模 → 打样 → 上架 → 运营 → 复盘，AI 负责起草，人负责拍板；一个 exe 装完即用。

## 为谁，解决什么

**用户**：1 个人 + 1~3 台 FDM 打印机的副业卖家 / 小工作室，在小红书等支持个人售卖的平台经营。

**问题**：机器把「生产」变简单了，但「做什么、怎么建模、怎么上架、怎么卖得动」仍靠人在十来个工具之间搬运。瓶颈不是机器，是**人的时间和试错次数**——2 台机器满负荷一天也就出 4 件，选错一个款的代价很高。

## 怎么解决

```mermaid
flowchart LR
  A["🔎 调研 Agent<br/>带证据的机会评分"] --> B["🎨 预览图<br/>建模参考 + 测款场景图"]
  B --> C["🧊 3D 模型<br/>AI 生成 / 导入 → 轻编辑 → 可打印"]
  C --> D["🖨 打样与定价<br/>成本 · 毛利 · 产能"]
  D --> E["🛒 发布包<br/>文案 + 图片 → 人工发布"]
  E --> F["📈 运营<br/>订单 · 打印队列 · 时效"]
  F --> G["🔁 复盘<br/>漏斗 · 实验 · 周报"]
  G -. 经验库 .-> A
```

| 目标 | 做法 | 量化 |
|------|------|------|
| 快速设计 | 调研 5 分钟出机会卡；出图 1 分钟；图生 3D 约 1 分钟；应用内切平底、定尺寸、查水密 | 想法 → 可打印文件：小时级 |
| 快速发布 | 成本定价器；多角度笔记草稿；合规检查；发布包（电脑端 / 手机扫码） | 点开发布包 → 发布完成 ≤ 2 分钟 |
| 高效运营 | 订单导入 → 打印队列按发货截止排序；48 小时 / 预售时效预警；内容日历 | 零超时发货 |
| 提高转化 | 截图识别录数 → 单品漏斗对比自己的基线 → 周报给出「下周只改这 1~2 处」 | 每周 30 分钟复盘 |

## 为什么值得做（调研证据）

- 需求在涨：2025 年小红书「3D 打印」搜索量 +238%，话题浏览超 16 亿。
- 同质化款已是价格战（关节龙 9.9 元），而「AI 出图 → 图生 3D → 打印」的**定制**玩法有人跑通（19.9 元定制链接月售约 4000 单，成品 268~288 元）。
- **没有产品覆盖全流程并适配小红书个人店**：海外工具管「订单→排产」，AI 建模工具止于模型，国内 ERP 对个人店过重，AI 笔记工具不懂打印、还有封号风险。

## 两个反直觉的产品决定

1. **不做「一键发布」。** 小红书没有笔记发布 API，电商 API 明文排除个人店与个体工商户，2026-03 起封禁托管发布的账号。所以「AI 起草打包 + 人工点发布」是正式形态，我们把它压到 2 分钟（[ADR-0002](adr/0002-channel-strategy.md)）。
2. **商品首图不用 AI 图。** 平台把「AI 批量换景」列为违规，差评也集中在货不对板。AI 图用于概念测款与氛围；首图强制实拍。

## 产品形态与技术

Windows 桌面应用，**单个 exe 安装包、零外部依赖**，数据全在本机，用户自带接口密钥。技术栈 Rust + Tauri 2 + Leptos + 内嵌 SQLite，工程约定对齐已发布的 velo（ztmail），安装包、签名、自动更新、凭据、后台队列、LLM 流式输出直接复用；three.js 查看器照搬 velo 嵌 PDF.js 的 JS 桥模式，几何运算全部在 Rust（[ADR-0001](adr/0001-tech-stack.md)）。

出厂默认的接口组合：DeepSeek（调研与识图）+ 智谱搜索 + MiniMax（出图）+ Tripo（图生 3D，只要白模）。每个单品的 AI 成本约 ¥6。

## 北极星与 90 天目标

**北极星**：每月「跑通单品」数——上架 30 天内订单 ≥ 10、毛利率 ≥ 50%、退款率 ≤ 10%。

| 90 天目标 | |
|-----------|---|
| 想法 → 上架周期（中位数） | ≤ 3 天（手工基线 1~2 周） |
| 每个单品人工耗时 | ≤ 2 小时（基线 8~15 小时） |
| 上架单品 / 其中跑通 | ≥ 12 / ≥ 3 |

## 路线

| 阶段 | 时间 | 出口标准 |
|------|------|----------|
| W0 地基与预研 | 第 1 周 | 签名安装包可装可更新；three.js 桥、几何内核、调研流水线三个预研通过 |
| MVP-α 想法→发布包 | 第 2~5 周 | 用它走通 3 个真实单品 |
| MVP-β 数据回流与订单 | 第 6~8 周 | 3 个单品在售且漏斗有数，无超时发货 |
| V1 效率与自动化 | 第 9~13 周 | 定制类单品跑通；微信小店 API；5~10 位外部卖家内测 |

## 最大的三个风险

| 风险 | 对策 |
|------|------|
| AI 生成的模型打不出来 | 生成时要求平底与定尺寸；应用内检测与清理；功能件走导入 / 参数化路线 |
| 外部用户上手难（要自己注册几家平台拿密钥） | 预设方案、逐步引导、能力降级、演示模式 |
| IP 侵权与品类合规 | 调研阶段一票否决；上架 Lint；模型许可证必选 |

## 要验证的关键假设

| 假设 | 怎么验证 |
|------|----------|
| AI 生成的模型经轻编辑就能打印并卖得出去 | 前 5 个单品的建模返工次数与一次打印成功率 |
| 概念图测款能预测真实销量 | 对比测款收藏率与上架后的转化 |
| 半自动发布足够快 | 实测「点开发布包 → 发布完成」耗时 |
| 截图录数可持续 | 每周录数耗时与识别后人工修改的字段数 |
