# ADR-0009 · 上架与发布包：AI 起草、合规检查、打包，人来点发布

状态：已采纳（2026-09-21）· 依据：[ADR-0002](0002-channel-strategy.md)（半自动发布是正式形态）、PRD M5

## 背景

0.9.5 为止，一件单品能走到「打样、定价」，然后就断了：上架要写的笔记、商品文案、要处理的图，全在应用外面做。M5 把这一段接上，目标是 PRD 里那句——**从实物到「手机上点发布」≤ 1 小时，其中从拿到发布包到发布完成 ≤ 2 分钟**。

约束来自 ADR-0002：小红书没有笔记发布接口，个人店也拿不到电商开放平台的接口；2026-03 起用托管工具或脚本发布的账号会被封。所以这里**不碰任何平台**：应用负责起草、检查、打包，点「发布」的永远是人。

## 决定

侧栏新增一级入口「上架」，排在「定价」后面（调研 → 图片 → 建模 → 定价 → **上架**）。三栏：左边选项目；中间是草稿（「笔记」「商品」两个标签页）和配图；右边是合规检查、发布包、回填链接。

### 1. 两种草稿，用的是 v1 就建好的两张表

- **笔记**（`content_posts`）：一个项目可以有很多篇。按**角度**起草——痛点 / 场景 / 过程 / 设计幕后 / 定制故事；同一个单品用不同角度各写一篇，是最便宜的测款方式。
- **商品**（`listings`）：一个项目在一个渠道上一条。标题、卖点、详情、售价（默认带入定价器里定的价）、预售天数、**模型来源**（原创 / 已购商用授权 / 非商用——非商用的不能卖）。

schema v6 只补了几列（软删除、AI 起草标记、放不进现成列的 `extra_json`），新增一张 `publish_packs`。加列仍然走 `add_column_if_missing`，有「升级到一半被打断」的测试。

### 2. 渠道规格和合规检查是前后端共用的纯函数（`pp_common::publish`）

和定价引擎同一个思路：界面上**边打字边出检查结果**，不用等后端；生成发布包时后端用同一套规则**再判一次，那一次才算数**——「检查没过不能出包」不能只靠界面自觉。

- 规格是数据：标题 ≤ 20 字、正文 ≤ 1000 字、话题 ≤ 5 个、笔记图 ≤ 18 张；商品主图 3~9 张、首图必须是实拍。数字的来源见 04-integrations §4.3 / §7.2；商品标题上限没找到官方数字，按 60 字从严。
- 检查结果带类型（`LintCode` + 命中的词 + 所在的栏），界面按类型本地化，和 `CadProblem` 同一个做法。
- **硬项**（拦）：字数 / 图片数量、极限词、功效与医疗宣称、品牌与角色名、站外导流（含手机号）、好评返现类表述、商品首图不是实拍、没填售价、没选模型来源或选了非商用。**提醒**（不拦）：用了 AI 生成的图（发布时要勾选平台的 AI 内容声明）、售价低于单位成本、品类预警（儿童用品、带电、接触食品、刀具造型）。
- 词表用**词组**而不是单字：「最」会误伤「最近」「最后」；「第一」后面跟着「步 / 次 / 眼 / 时间…」时是序数，不算。
- **可以强制跳过，但要写原因**：原因和当时没过的项一起存进发布包（`override_reason` + `lint_json`）。和阶段门的「跳过要写原因」是同一个思路——不拦死，但留痕。

### 3. AI 起草是一次有界的调用（`pp_agent::publish`）

- 一次调用出全部候选（JSON 模式，不流式）。写文案要的事实从项目里拼：名称、品类、假设（谁会买、为什么）、名下模型的尺寸、定价器里的售价、资料库级的**品牌语气**。提示词要求「没给的参数不要编」。
- 输出违反硬规格或命中违禁词 → 带着原因**重问一次**；第二次还有问题就照样交回来，界面上的检查会标出来——人改一个词比再花一次调用划算。结构不对（篇数不够、空标题）才算失败。
- 可以中途停止（`publish:<项目 id>`）；花费照常记进账本。演示模式有脚本化的回答，不填密钥也能走完整条线。
- 模型用强的那个（`deepseek-v4-pro`，不开思考）：文案要的是语感，一次两三千 token，差价可以忽略。

### 4. 发布包是资料库里的一个文件夹，出过的都留着

`packs/<项目编号>/<note|listing>-<id 尾段>/`：按顺序编号的图（统一处理成 1080 × 1440 的 JPEG，超过 3 MB 逐级降质量）+ `标题.txt` / `正文.txt` / `话题.txt`（商品是 `商品信息.txt`：标题、卖点、售价、规格、发货方式）。文本带 BOM，记事本不会认错编码。

- 图片两种放法：**裁切填满**（生活场景图）/ **留白适应**（白底产品图）。重新编码的同时去掉了 EXIF——手机拍的实拍图里有 GPS。
- 配图从哪来：导入的**实拍图**（新资产类型用的是早就有的 `Photo`）+ 这个项目在图片工作台里的图。AI 图带标记，检查靠它判断「首图是不是实拍」。
- 再出一次不覆盖旧的（和「AI 产出默认是候选、再生成不覆盖旧版本」同一个原则）。
- 文件夹名取 ID 的**随机尾段**：ID 是 UUIDv7，前缀是时间戳，一分钟内出的几个包前 8 位一样——端到端验证时第二个包把第一个覆盖了，才发现这一点。

### 5. 两种发布方式，都是人来点

- **方式 A · 在电脑上发布**：打开素材文件夹；用默认浏览器打开渠道**官方的**发布页；按「标题 → 正文 → 话题」逐项复制，复制一项、下一项高亮。
- **方式 B · 用手机发布**：应用临时开一个**只读的局域网页面**，手机扫码打开。只用标准库写的小服务（`src-tauri/src/share.rs`）：
  - 端口由系统随机分配；路径里带 128 位的一次性令牌，令牌不对一律 404；只认 GET，只发这一个包里的文字和图片；带 CSP、`no-store`、`nosniff`。
  - 用完即停：离开上架页、换一个包、空闲 20 分钟、应用退出。
  - 连接是串行处理的，浏览器（手机上也一样）会预开几条什么都不发的连接——等请求行只等 1.2 秒，停止时最多等服务线程 2.5 秒。端到端验证时踩到过：每条空闲连接等 5 秒，「停止」被拖了十几秒。
  - **和 PRD 原稿不一样的地方**：原稿写的是四个按钮，其中一个是「保存全部图片」。做不了——局域网页面是 HTTP，不是「安全上下文」，批量保存（Web Share）和剪贴板接口在手机浏览器里都不可用；给局域网地址配 HTTPS 要用户信任自签证书，更不现实。所以页面上是三个复制按钮（走 `execCommand('copy')`，HTTP 下也能用；失败时提示长按文字手动复制）+ 图片列表（长按保存到相册，这是两个平台都支持的标准手势）。
  - 第一次用会触发 Windows 防火墙的授权提示，界面上提前说明了。自动化验证时传 `lan = false` 只监听回环，不触发这个提示。

### 6. 回填链接，项目往前走

发布完把链接贴回来 → 这个包和它的草稿标成「已发布」。项目的「上架」阶段从此有清单：**出过发布包 + 回填了链接**。项目正停在「上架」、这一下让清单齐了 → 自动进入「运营」（PRD 的验收项；往回拖随时可以）。看板卡片、项目中枢、右键菜单里都有进「上架」的入口。

## 验证

- 单测：规格与检查（误伤用例：「第一步」「最后」不算极限词；手机号 11 位的边界；AI 图能配笔记、不能当商品首图）、仓储（一个项目一个渠道只有一条商品；价格按分存；出包和回填对草稿状态的影响；v5 → v6 被打断重跑）、起草（违规 → 带原因重问一次 → 第二次照样交回）、图片处理（裁切 / 留白的像素位置、透明底铺白、超限降质量）、手机页（令牌、只读、路径穿越、`</script>` 注入、空闲连接不拖住请求和停止）。
- 真实界面（演示模式 + 一次性项目）：出图并采用 → 导入实拍 → AI 起草两篇 → 出包（文件夹里 1080 × 1440、无 EXIF、带 BOM 的文本）→ 标题里写「全网第一」被拦、写了原因放行并留档 → 商品：AI 图打头 / 只有一张 / 没选来源被拦，改对了出包 → 手机页（回环）：页面 200、图片 200、错令牌 404、POST 405，用手机尺寸看过排版 → 回填链接（`javascript:` 被拒）→ 项目自动进入「运营」。

## 没做的（按 PRD 的优先级往后排）

- 封面变体与实验、内容日历（只提醒不代发）、闲鱼文案适配与经营性阈值计数——P1。
- 微信小店 API 渠道——P2，前提是用户有个体工商户执照。
- IP 名词只查内置词表；「被模型判为高风险」那一半、用户自定义词表还没做。
- 手机页的复制按钮没有在真手机上点过（本机只能用桌面浏览器按手机尺寸看）；真实的 DeepSeek 接口仍未实测。
