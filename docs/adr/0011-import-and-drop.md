# ADR-0011 · 自己的图也能进来：导入、拖入、粘贴

状态：已采纳（2026-09-22）。Windows 上已实现并验证；**真的从资源管理器拖一个文件进来这一步，和 macOS，还没有验证过**（见文末）。

## 背景

图片工作台里的图只能靠生成。唯一能把本地图片带进来的办法是对话栏里的「贴一张图」——那张图只跟着那一句话走：不能选中、不能采用、不能导出、不能送去建模，也进不了发布包。

而卖家手里本来就有图：样品的实拍、手画的草图、从别处找来的参考。负责人的原话（2026-09-22）：「现在图片只能生成，无法自己导入，这不对，可以导入本地图片，比如直接拖入」。

## 决定

**1. 导入的图是画板上的一等公民。** 它就是 `image_versions` 里的一行，`mode = "import"`（`generate / edit` 之外的第三种，列本来就是文本，**不改 schema**），没有提示词、没有供应商。于是生成的图能做的事它都能做：选中、采用（项目「概念」阶段的那一项清单因此可以用自己的图来满足）、导出、送去建模、让 AI 接着改（「把背景换成纯白」改的就是这张实拍）。资产记 `role = studio_import`、`ai_generated = false`——发布包里「这张是不是 AI 生成的」跟的是资产上的这个标记；从导入的图**改**出来的图照常是 AI 生成的。胶片条上导入的图右下角带一个小标记。

**2. 三个入口，同一条管线**（`command/imagery.rs::import_into_board`）：

- 「导入图片」：没图时在大图区中间，有图之后是胶片条最前面的那一格；大图周围空白处的右键菜单里也有。可以多选。
- **直接拖进窗口**。
- **粘贴**：`Ctrl+V`，或右键菜单「粘贴图片」。剪贴板里是位图（截图、浏览器里「复制图片」）或者是复制的图片文件（资源管理器里 `Ctrl+C`）都行——图由后端用 `arboard` 去读，WebView 里只拿得到一个没有路径的 `File`。

一个画板都没打开时，导入会先建一个。

**3. 落点决定去向。** 拖到画板这边（列表、大图、胶片条）= 导入成画板上的图；拖到对话栏 = 只贴到这句话上当参考（原来「贴一张图」的语义，一轮最多 3 张的限制照旧）。悬着的时候两块地方各有一个虚线框说明松手之后会发生什么，光标在哪边哪边亮。粘贴同理：焦点在对话输入框里 = 贴到这句话上，别处 = 导入。剪贴板里既有字又有图时（从网页、文档里复制的一段），在输入框里按文字粘。

**4. 入库前的处理**（`prepare_import`）：

- 按 EXIF 摆正，然后**重新编码一遍**——为的是去掉元数据：手机照片里有拍摄地点和机型，而这张图之后会发给第三方模型、会发到平台上。
- 最长边超过 4096 就缩到 4096：够发布图（1080 × 1440）裁切放大用，又不至于把几十 MB 的原片原样塞进资料库。
- 真有透明像素的存 PNG（抠好的产品图不能被铺白之后再也抠不回来），其余存 JPEG（质量 92）。
- 剪贴板里的位图经常整张 alpha = 0：那是来源没填，不是全透明，当成不透明处理。
- 认 PNG / JPG / JPEG / JFIF / WebP（按扩展名先筛一道，真正认不认得看解码）。**HEIC、AVIF 解不了**：`image` 库要靠原生解码器，和「单个安装包、零依赖」冲突——给的是一句明白话：「请先另存为 JPG」。
- 一次最多 20 张；**一张坏图不让整批作废**：能导入的照常导入，导不进来的逐个给出文件名和原因。

**5. 时间线上记一条「导入了 N 张」**，靠右（是用户做的事），点其中一张就选中它。这条消息没有文字，所以不会进给规划模型的对话历史；规划模型那边，当前图没有提示词时会被告知「这是用户自己导入的图，不是模型生成的」，要重新生成的话提示词得照着画面从头写。**导入不给画板起名**——起名仍然靠第一句话（「IMG_20260921」不是一个好名字）。

**6. 送去建模时先做成参考图。** 建模把参考图原样发给视觉模型；导入的原片（最长边可以到 4096）和带透明的 PNG 会先另存一张参考图（缩到 1536、铺白、JPEG，和「贴参考图」入库时的处理一样），本来就不大的 JPEG 直接用。

**7. 拖放用 Tauri 的原生事件，机制是全局的。** Tauri 默认接管了文件拖放（`dragDropEnabled`），WebView 里的 HTML5 拖放收不到本地文件的路径；用的是 `tauri://drag-enter / over / drop / leave`（`src/app/mod.rs::listen_file_drops`，和别的后端事件一样在 App 里只注册一次）：

- 悬着的时候写 `state.file_drag`（路径 + 光标位置），页面读它来画提示；松手时交给**当前页面登记的处理函数**（`state.accept_file_drops(..)`，在页面组件体里调用，卸载时自动撤掉）。
- 事件里的坐标是**物理像素**，换成 CSS 像素再给页面——页面要拿它和元素的 `getBoundingClientRect` 比。
- 换页时新页面**先**挂载、旧页面**后**卸载：撤登记时只撤自己登记的那一个（带编号），否则会把新页面刚登记的撤掉。
- 没登记的页面不收文件；拖进来的是图片的话提示一句「请拖到『图片』工作台里」。

同一套机制顺手接了另外两处本来就只有「选文件」按钮的地方：**建模**（拖进来的图 = 参考图；还没打开设计就先新建一个——「从一张图开始」本来就是建模的起点）和**上架**（拖进来的图 = 这个项目的实拍图，按钮也改成了可以多选）。

## 没有选的路

- **关掉 Tauri 的原生拖放、改用 HTML5 拖放**：拿不到路径，图得以字节形式穿过 IPC（几十 MB 的照片 base64 之后再涨三分之一）；看板的拖拽当初也是因为 WebView 里的 HTML5 拖放不可控才改用指针事件的。
- **原样保存原图**：EXIF 里的位置信息会跟着图一起发出去；一张手机原片十几 MB，20 张就是几百 MB。
- **用文件名给画板起名**：相机和下载的文件名大多没有意义，还会挡住「第一句话起名」。
- **支持 HEIC / AVIF**：要带原生解码库。等真的有人被它挡住再说——那时更可能的做法是调系统自带的解码能力，而不是把解码器打进安装包。
- **拖文件夹进来、递归导入**：一次误操作就是几百张图。文件夹会被逐个说明「不支持」。

## 验证到哪一步

在真实的开发版应用里（Windows，2026-09-22）走过：

- **拖入**：悬着时两块落点随光标切换；拖的不是图片时只显示一句「只能导入图片」；移出窗口提示消失。一次拖进 2 张好图 + 1 张坏图 + 1 个 HEIC + 1 个 txt → 2 张导入（不透明的成了 JPEG、带透明的保留 PNG、记了原文件名），第一张成为当前图，另外 3 个逐个说明原因；一个画板都没有时拖进来 → 自动建画板并导入；拖到对话栏 → 只贴成这句话的参考图（受「一轮最多 3 张」限制），画板上不多图。
- **粘贴**：剪贴板里是位图（用应用自己的「复制图片」放进去的）→ 导入成一张图；是复制的文件（一张图 + 一个 txt）→ 只导入那张图、带文件名；只有文字 → 「剪贴板里没有图片」；界面上的粘贴事件（不在输入框里）→ 走导入。
- **导入之后**：演示模式下对导入的图说「背景换成木纹桌面」→ 出了一张改图，父图是导入的那张、标记为 AI 生成，画板照常由这句话起名；「送去建模」一张 1600 × 1200 的导入图 → 设计的参考图是另做的 1536 × 1152 JPEG（父资产是原图），这张图被标为已采用。
- **建模 / 上架**：没打开设计时拖一张图进「建模」→ 新建设计、图成为待发的参考图；拖两张图进「上架」→ 成为该项目的实拍图。
- 测试用的画板、设计、项目和资产都已删除；演示模式已关回去。

**这些拖放是用 Tauri 的事件模拟的**（`event.emit('tauri://drag-drop', …)`，载荷格式和坐标单位照着 Tauri 源码核对过）：调试通道没法从资源管理器里真的拖一个文件进来，**真实的系统级拖放还要手动试一次**——重点看松手的位置判得对不对（落在对话栏 / 落在画板）。macOS 完全没有验证过（拖放坐标、`arboard` 读剪贴板里的文件列表）。
