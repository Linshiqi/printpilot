# ADR-0008 · 右键菜单：拦掉浏览器自带的，换成按位置和上下文给出的应用内菜单

状态：已采纳（2026-09-21）

## 背景

应用跑在 WebView 里。不做任何处理时，任何位置点右键出来的都是浏览器自带的菜单——「返回 / 刷新 / 另存为 / 打印 / 更多工具 / 检查」。在一个桌面应用里这几项没有一项是对的：「刷新」会把整个界面的状态冲掉（正在跑的一轮对话就断了），「检查」把开发者工具暴露给用户。负责人在试用 0.9.4 的本地构建时指出了这一点，要求「根据点击位置和当前上下文」给出菜单。

## 决定

三层，代码都在 `src/ui/context_menu.rs`（整体做法参考 velo 的 `context_menu.rs` + `edit_menu.rs`）：

1. **全局兜底**（`install`，App 启动时装一次）：窗口级的 `contextmenu` 监听，**一律** `preventDefault`。然后按落点给通用菜单：
   - 输入框 → 剪切 / 复制 / 粘贴 / 全选（做不了的置灰，不隐藏）；
   - 一张资产图片（`<img src="…pp-asset…">`）→ 复制图片 / 用默认程序打开；
   - 页面上选中了一段文字 → 复制；
   - 其余位置 → 不出菜单。
2. **具体对象的菜单**：元素上写 `on:contextmenu=move |ev| state.open_menu(&ev, vec![…])`。现在有菜单的对象：看板卡片；建模页的设计行、3D 视图、版本行、对话消息、参考图；图片页的画板行、每一张图（胶片条 / 中间的大图 / 对话里的图）、对话消息；调研历史；定价页的项目行、打样记录、打印机 / 耗材档案。
3. **宿主**（`ContextMenuHost`，App 里挂一次）：画、定位、关闭、键盘操作。

几条具体的取舍：

- **菜单项由调用方给，而不是 velo 那样「宿主按目标类型自己拼」**。velo 有一个总控制器，宿主拿到 `MenuTarget::Email(env)` 就能自己去调；PrintPilot 的操作散在各个页面的闭包里（`rename`、`export`、`select_version`…），让宿主认识所有页面不现实。所以 `open_menu` 收的是 `Vec<MenuEntry>`，每项带一个 `Arc<dyn Fn() + Send + Sync>`。
- **菜单里只放界面上已经有的操作**。它是捷径，不是另一套功能——不会出现「只有右键才能做」的事。唯一新增的能力是「复制图片」和「复位视角」，前者在通用图片菜单里，后者在 3D 视图菜单里。
- **对「这一个」操作，不要求先选中它**。右键列表里的一个设计点「删除」，删的就是它——不用先打开；右键胶片条里的一张图点「采用」，采用的就是它——不用先设为当前。为此几个页面的操作从「对当前对象」改成了「对指定对象」（`delete_target` / `remove_target` / `adopt_version(v)` / `export_version(id)`…）；删除确认框里写明对象的名字，因为要删的可能不是眼前打开着的那个。
- **做不了的操作置灰，不隐藏**（当前这版上的「切到这一版」、没有模型时的「导出」）：同一个对象的菜单每次长得一样，比「这次有、下次没有」好找。破坏性的操作放最后、红字、仍然走原来的确认框。
- **粘贴和复制图片走后端**（`arboard`）：WebView 自己读剪贴板（`navigator.clipboard.readText`）在 Windows 上要弹权限框；图片放进剪贴板的是解码后的位图，所以微信、小红书网页版、画图里都能直接粘贴。剪切 / 复制 / 全选用 `document.execCommand`；粘贴用 `insertText`——会触发 `input` 事件（界面上绑的信号跟着变），也进得了撤销栈。
- **菜单从不抢焦点**：菜单项上 `mousedown` 被 `preventDefault`。所以「剪切 / 复制 / 粘贴」执行时，焦点和选区都还在原来那个输入框里。键盘操作（↑ ↓ 回车 Esc）因此挂在窗口上，菜单开着时把这几个键吃掉。
- **3D 视图：右键拖动是平移视角，拖完不弹菜单**。记下右键按下的位置，松手时离它超过 4 像素 = 刚才是在拖。`contextmenu` 什么时候来各平台不一样：Windows 在松手之后（`buttons` 已经是 0）→ 当场判断；macOS / Linux 在按下的那一刻（右键还按着）→ 先只拦掉浏览器的菜单，等 `pointerup` 再判断。
- **在菜单外面再点一次右键**：关掉这个，并把这次右键转交给底下的元素（等底板撤掉后用 `elementFromPoint` 找到它，补发一个 `contextmenu`）——和系统菜单的手感一致，不用先点一下关掉再点一次。
- **定位不量高度**：点在视口下半部分就向上展开（用 `bottom` 定位）；横向按菜单的最大宽度留出右边的空间。窗口失焦、改尺寸、滚轮 → 关。
- 层级：菜单 `z-[300]`，在对话框（110）和提示（200）之上——对话框里的输入框也要有编辑菜单。

## 验证

纯逻辑有单测（整理分隔线、定位不出视口、上下键跳过置灰项并绕回、从图片地址里认出资产 ID）。其余在真实界面里用 CDP 验证：每种对象的菜单项和置灰状态；从菜单改名（没打开的设计 → 先打开 → 输入框拿到焦点并全选）；打开着甲、右键删乙（确认框写的是乙，删完甲还开着）；3D 视图的开关项打勾、右键拖动后不弹菜单；键盘 ↓ ↓ 回车 / Esc；在别处再右键会换成那里的菜单；贴着右下角时向上展开且整个在视口内；空白处不出菜单、浏览器菜单被拦掉；没完成清单时从卡片菜单「进入下一阶段」照样弹出要原因的对话框。

**剪切 / 复制要用真实的鼠标点击来测**（`scripts/cdp.py rclick` + `click`）：`execCommand('cut' / 'copy')` 需要「用户手势」，合成事件触发的会被浏览器悄悄拒绝。

## 没做的

- 子菜单（「移到项目…」这类）。现在没有需要它的操作；关联项目仍然用工具栏上的下拉框。
- 3D 视图里「按下时就来的 `contextmenu`」那条路径（macOS / Linux）只按规范写了，没有在真机上点过——本机只有 Windows。
