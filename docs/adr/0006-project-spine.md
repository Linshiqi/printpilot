# ADR-0006 · 项目是主线：三个工作台挂在项目名下，阶段门清单从产出里算出来

- 状态：**已采纳**（2026-09-21，负责人指出：「三个工作台各自独立，它们之间只有图片 → 建模一条线，和项目只有一个关联下拉框，项目阶段不驱动任何东西」）
- 前置：[ADR-0004](0004-modeling-studio.md)（建模工作室）、[ADR-0005](0005-image-studio.md)（图片工作台）
- 影响：[01-prd.md](../01-prd.md) §4 / M0、[02-ux-flows.md](../02-ux-flows.md)、[03-architecture.md](../03-architecture.md) §9

## 背景

0.9.2 为止，调研、图片、建模三块各自能用，但彼此是孤岛：

- 调研还躲在「预研」页的一个页签里，没有历史，结果不挂项目；
- 画板和设计能「关联到项目」，但那只是一个下拉框——项目那边看不见它们；
- 看板上挪卡片纯靠手动，阶段不代表任何事实；「跳过阶段要写原因」只看跨了几格，不看活儿干没干。

产品的北极星是「想法 → 发布包 ≤ 1 天」。要量这件事，**项目**必须是主线：一个单品走到哪一步、每一步产出了什么、卡在哪，都得在项目上看得见。

## 决定

1. **三个工作台都能独立用，也都能从项目里发起**。从项目里发起时：产出直接挂在项目名下（`project_id`），输入框里先放一句由项目名称、品类、假设拼出来的草稿（用户可以改，不自动发送）。
   - 调研升为侧栏一级入口「调研」（原「灵感池」的位置），排在「图片」「建模」前面——按一个单品走过的顺序；有了历史；可以选「为哪个项目调研」，也可以不挂项目（先找机会，看到好的再「采用为项目」）。
   - 「预研」页只剩 3D 模型工具。
2. **阶段门清单不是手工打勾的，是从名下的产出里算出来的**（`pp_common::gate`，纯函数，前后端共用）：

| 阶段 | 离开之前该有 | 从哪来 |
|------|--------------|--------|
| 灵感 | 写下了要验证的假设 | 项目的「假设」非空 |
| 调研 | 有一份调研报告 | 名下的 `research_runs` |
| 概念 | **采用**了一张预览图（光出图不算） | 名下画板里 `adopted` 的图 |
| 建模 | 建出了一个模型（光有设计不算） | 名下设计有 `current_version_id` |
| 打样 | 有一次**成功**的打样记录 + 在定价器里定了售价（0.9.4 起，[ADR-0007](0007-cost-pricing.md)） | 名下的 `print_runs`、`cost_models.chosen_price` |
| 上架 · 运营 · 复盘 | —— 工具还没做出来，清单是空的，靠人判断 | M5 ~ M7 做出来之后补 |

   空清单的含义是「没法自动判断」，**不是**「完成了」：这些阶段永远不会自动显示「可推进」。
3. **阶段驱动下一步**。项目抽屉升级成**项目中枢**：阶段条 → 「离开这个阶段之前」卡（清单 + 这个阶段该去的工作台的按钮 + 进入下一阶段）→ 名下的调研 / 图片 / 模型（点开就回到对应的工作台）→ 基本信息 → 流转时间线。到现在的 AI 花费显示在顶上。
   - 「建模」阶段的按钮会看名下有没有采用的图：有就拿它当参考图开设计（同图片工作台的「送去建模」）。
   - 工作台里挂了项目的画板 / 设计旁边有一个「打开项目」按钮——中枢是全局抽屉，盖在当前页面上，不用离开工作台。
4. **要不要写原因，看证据，不看跨了几格**（替换掉原来的「往前跳过至少一个阶段才要原因」）：
   - 往回挪（返工）永远不用；
   - 路过的阶段里有清单项没完成 → 要（哪怕只走一步）；对话框里**列出到底缺什么**；
   - 证据齐了，一次跨两格也不用解释；
   - 整个跳过一个没法自动判断的阶段（从「建模」直接到「上架」）→ 要；只是顺着走出这样一个阶段（「打样」→「上架」）不用。

   **后端按同一套规则再判一次**（`move_project_stage` 不再相信前端传来的 `forced`）：该写原因而没写 → 拒绝；`stage_events.forced` 由后端根据证据写入。
5. **看板卡片上看得见产出**：调研 / 图 / 模型的计数小图标；当前阶段清单完成时显示「可推进」。一条 `project_facts_all` 查询取回所有项目的计数；工作台里做了可能改变清单的事（出图、采用、拿掉、建出模型、关联项目、保存假设、调研完成）之后重新数一遍。
6. **不自动推进阶段**。清单完成只是提示 + 一个主按钮；挪不挪由人定——「AI 负责起草，人负责拍板」。

## 数据

没有新表。用到的都是已有的关联：`research_runs.project_id`、`image_boards.project_id`、`cad_designs.project_id`、`cost_entries.project_id`。新增两条只读查询（`pp-db/src/overview.rs`）：所有项目的产出计数、单个项目的总览。

## 没有选的路

- **完整的项目详情页（每个阶段一个标签页）**：PRD 的长期形态。现在后四个阶段还没有东西可放，先用加宽的抽屉当中枢；M4 / M5 做出来之后再升级成整页。
- **清单完成就自动挪到下一阶段**：省一次点击，但会让看板上的位置不再代表「人的判断」，复盘时分不清是人推的还是机器推的。
- **手工可勾选的清单项**（PRD 里设想过）：先不做。能从事实里算出来的就不让人勾；算不出来的阶段等工具做出来再说。
- **在工作台里按项目筛选列表**：画板 / 设计还不多，先靠中枢里的入口；多了再加。
