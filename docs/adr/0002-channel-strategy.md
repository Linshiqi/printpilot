# ADR-0002 · 渠道接入策略：半自动发布是正式形态，不做非官方自动化

- 状态：**已采纳**（2026-09-20）
- 依据：[04-integrations.md](../04-integrations.md) §7

## 背景

需求里写的是「接入小红书等支持个人售卖的平台」。联网核实后的事实是：

1. 小红书**没有笔记发布 API**；官方分享 SDK 只能拉起 App 发布页并带入图片 / 视频，已不支持自动填充标题、文案、话题。
2. 小红书电商开放平台的「商家自研」**明文要求店铺类型非个人 / 个体工商户**；服务商通道需要成立满一年的企业与每应用 1~2 万保证金。也没有经营数据 API。
3. 2026-03-10 起，小红书封禁通过托管工具注册、发布、互动的账号（媒体称已治理 120 万+ 账号）；有用户用脚本操作网页版定时发布后被封。
4. 闲鱼、抖店、淘宝、拼多多对个人店都没有可行的自研 API 通道。
5. **微信小店**不接受个人入驻，但个体工商户可以在后台直接拿到自研凭据，接口覆盖商品、订单、售后、物流。

## 决定

1. **「AI 起草 + 打包，人工发布」是产品的正式形态**，不是等接口期间的临时方案。我们把人工环节压到 2 分钟以内，而不是想办法绕过它。
2. 渠道适配器用**能力声明**描述每个渠道能做什么（发布内容 / 发布商品 / 同步订单 / 回收数据 各自是 人工、文件、截图 还是 API），界面按能力自动降级或升级。
3. **红线**：不实现、不集成、不以「可选插件」形式提供任何非官方自动化——模拟登录、逆向接口、浏览器自动化发帖、定时代发、自动互动、站内数据抓取。理由：账号是卖家的核心资产，一次封号抹掉的价值远大于自动化省下的时间；对作为发行方的我们也有法律风险（已有抓取小红书数据被判赔 490 万元与刑事判例）。
4. 渠道优先级：小红书（半自动，首发）→ 微信小店（API，V1，面向已办个体工商户执照的用户）→ 闲鱼（文案适配 + 经营性阈值提醒）。其余暂不投入。
5. 数据回收的统一入口是「指标快照」：API / 官方导出文件 / 截图识别 / 手填四种来源同表，人工核对后入库。

## 影响

- 正面：零封号风险；不依赖任何平台的资质审批即可上线；适配器形态为将来的官方接口留好了位置。
- 负面：发布与录数仍需人工，每篇笔记约 2 分钟、每周录数约 10 分钟——用发布包、逐项复制、截图识别把这部分压到最低。
- 需要向用户讲清楚：为什么不做「一键发布」。在发布包界面用一句话说明，并链接平台公告。
