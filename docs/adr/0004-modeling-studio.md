# ADR-0004 · 建模工作室：一级入口 + 和 AI 的持续对话

- 状态：**已采纳**（2026-09-21，负责人指定：「建模是核心功能，要有独立入口，要能和 AI 持续对话修改和微调，要做好做全」）
- 前置：[ADR-0003](0003-code-cad-build123d.md)（看图 → build123d 代码式 CAD、沙箱执行、引擎随安装包分发）
- 影响：[01-prd.md](../01-prd.md) M3、[02-ux-flows.md](../02-ux-flows.md)、[03-architecture.md](../03-architecture.md) §8 / §9

## 背景

0.9.0 里代码建模放在「预研」页：一次性的表单（参考图 → 出规格 → 生成），修改靠一个「指令」输入框，每次指令互相独立、AI 不记得上一句说过什么。两个问题：

1. **位置不对**。建模是产品的核心能力，不是一项「技术验证」。
2. **交互不对**。真实的建模过程是来回的：「线槽宽一点」「再宽一点」「不对，改回去，换成 U 形底」「这个要加支撑吗」。一次性的指令框接不住这种过程——没有上下文、分不清「要改模型」和「只是问一句」、改参数和 AI 修改是两条互不相干的线。

## 决定

1. **「建模」成为侧栏一级入口**（`Route::Studio`，`src/view/studio/`）；预研页只留 3D 视图桥和调研两个验证面板。
2. 引入**设计（design）**作为一等实体：一个零件的一条建模线索 = 参考图 + 设计规格 + **对话时间线** + 版本树。可命名、可关联到项目、列表里有缩略图。
3. **对话是主线**，其它修改方式都并进同一条时间线：

| 时间线上的东西 | 谁产生 | 产出 |
|----------------|--------|------|
| 用户的话（可带图、可带在模型上点选的位置） | 用户 | — |
| 规格卡 | AI（还没有模型时，用户说的每句话都会更新规格） | 可「生成模型」/「编辑规格」 |
| 改好了 | AI（对话修改、按规格生成） | 新版本；显示改了哪些段、自动修复了几轮、可一键撤销 |
| 没改成 | AI | 最后一版代码 + 每一轮的真实报错，可放进编辑器手改 |
| 回答 / 反问 | AI | 纯文字，不动模型 |
| 复核结论 | AI（看图复核） | 差异清单，每条一键变成下一句话 |
| 事件：改参数、手改代码运行 | 用户 | 新版本（不经过模型、不花钱） |

4. **一次模型调用同时完成「判断意图」和「干活」**：回答里有 ```python 围栏 = 改了模型（整份脚本），没有 = 回答或反问。不另设一次「意图分类」调用——省一次往返，也避免分类器和执行者意见不一。改模型的那一支直接接进 ADR-0003 的「执行 → 检查 → 带着真实报错修」循环（第一版回答已经在手，不重问）。
5. **上下文怎么给**：当前脚本**永远**随消息一起给（用户可能刚手动改过参数，脚本才是事实）；之前的对话只给文字、只留最近 12 句（每句 ≤ 400 字，总共 ≤ 4000 字）；手动改参数这类事件以用户的口吻告诉模型；失败的那一轮明确告诉模型「没改成」。
6. **对话中途贴的图**：写代码的模型看不见图（DeepSeek 只有 flash 有视觉），所以先让视觉模型结合这句话把图描述成文字，再交给写代码的模型；这张图同时并入参考图（只留最新 4 张），之后的看图复核会对照它。
7. **分叉与撤销靠版本树，不靠删除**：选中旧版本再说话 = 从那一版分叉；「撤销」= 选回这次修改所基于的版本。什么都不删，时间线始终完整。
8. **一轮对话要么整轮入库，要么什么都不留**：模型调用失败（没密钥、断网、限流）不写半轮消息，用户的话留在输入框里，改好再发。
9. **模型档位由用户权衡**（输入区的「快 / 均衡 / 精细」）：快 = flash 不思考；均衡 = v4-pro 不思考（默认）；精细 = v4-pro + 思考。按规格生成第一版固定用精细——那是最难的一步。
10. 演示模式有一段**内置的对话脚本**（两种修改 + 一种回答），代码照样在真引擎上执行——不填密钥也能完整体验对话式修改。

## 数据（schema v3）

`cad_designs`（名称、项目、规格、参考图、当前版本、缩略图）· `cad_messages`（角色 user / assistant / event；类型 text / spec / build / failed / review / param / manual；随类型而定的部分存一列 JSON）· `cad_versions.design_id`。v2 已随 0.9.0 发布，只追加不修改；0.9.0 在预研页建的版本留着，只是不属于任何设计。

## 没有选的路

- **开放式 Agent（工具调用循环）**：让模型自己决定调用「改参数 / 执行 / 截图」等工具。更灵活，但每轮的成本和耗时不可预期，也更难做回归测试。现在这种「一问一答 + 有界修复循环」已经覆盖了建模对话里的真实需求；等真模型实测之后再看要不要放开。
- ~~**流式输出**：先用进度事件顶着~~ → 2026-09-21 已做，见下面「流式与取消」。
- **把每次对话的历次脚本都带进上下文**：贵，而且会诱导模型照着旧脚本改。

## 流式与取消（2026-09-21 补）

负责人要求：回复要流式、一轮开始后要能中途取消。

1. **流式走供应商适配层的一个新方法** `LlmProvider::chat_stream(req, sink)`：片段交给回调，最后返回和 `chat` 一样的完整回答（含用量——请求里带 `stream_options.include_usage`，否则流式响应里没有用量，钱就算不出来）。不支持流式的供应商用默认实现（整段当一个片段）。SSE 解析是一个纯状态机（`SseParser`）：**按字节攒、按整行解**（一个汉字都可能被切在两个字节块里），认注释行（DeepSeek 用它保活）、中途的 `error`、没等到 `[DONE]` 就断了的流。
2. **只有「给人看的自由文本」走流式**：对话回答、写代码、修代码。JSON 模式的调用（出规格、复核、调研、出图规划）不流——半截 JSON 没法给人看。中途贴图时让视觉模型描述图的那一段也不流：那是给写代码的模型看的中间产物。
3. **界面上显示什么**：思考模式下先显示思维链的**最后一小段**（灰色斜体；它可能有几千字，而且是给模型自己看的）；正文到了就换成那句话的气泡；写到代码围栏之后**只报行数**（「正在写代码 · 已写 N 行」）——对话栏很窄，几百行代码刷过去没有意义。
4. **片段节流**：后端攒 50 毫秒发一次事件（`cad-stream`）；任何一个「步骤」事件之前先把攒着的发完，所以尾巴不会丢。坏响应要重问时发一个 reset，界面清掉已经显示的片段。
5. **取消 = 丢掉正在等的那个 future + 杀掉正在跑的脚本**（`src-tauri/src/turns.rs`）。每一轮登记一个作用域键（`design:<id>` / `board:<id>` / `research`），`cancel_turn(scope)`：
   - 等模型 / 图片接口的请求被丢掉 → 连接关闭，供应商停止生成；
   - 建模引擎里正在执行的脚本约 0.1 秒内被杀（`pp_cad::CancelFlag`，常驻进程和单次执行都认）——不用等 90 秒超时。
6. **只有花时间的那一段可以取消；一旦开始落盘入库就不再理会取消**。这样「一轮要么整轮入库，要么什么都不留」在取消时依然成立：被取消的一轮什么都不写，输入框里的话还在。
7. 取消不是故障：错误码 `cancelled`，界面不弹红色错误，只轻轻说一声「已停止」。
8. **如实告知**：已经生成的 token、已经发出去的出图请求，供应商照样计费；取消省下的是还没生成的那部分。被取消的那一轮的花费我们算不出来（用量在流的最后一块里），所以不记账——这是已知的小缺口。
9. 演示模式的假模型也按片段吐字（每 24 个字符停 35 毫秒）：不填密钥也看得见流式，也来得及点「停止」。
