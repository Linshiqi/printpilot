# ADR-0005 · 图片工作台：接图片模型出图 + 和 AI 的持续对话改图

- 状态：**已采纳**（2026-09-21，负责人指定：「添加图片生成编辑工作台，与模型一样，要能接入图片生成模型 API，并能持续对话编辑修改」）
- 前置：[ADR-0004](0004-modeling-studio.md)（建模工作室：对话是主线）
- 影响：[01-prd.md](../01-prd.md) M2、[03-architecture.md](../03-architecture.md) §8 / §9、[04-integrations.md](../04-integrations.md) §4

## 背景

产品链路是「调研 → 预览图 → 3D 模型 → 定价 → 发布」。0.9.1 之前「预览图」这一环是空的：建模工作室要参考图，用户只能自己去别处找图；笔记配图、封面也没有着落。

出图和建模是同一种工作——**来回改**：「白底的」「再来几张」「就这张，背景换成木桌面」「颜色改成橙色」「这张能当封面吗」。所以它不该是一个「填提示词 → 点生成」的表单，而应该和建模工作室同构：一条和 AI 的对话。

## 决定

1. **「图片」成为侧栏一级入口**（`Route::Images`，`src/view/imagery/`），排在「建模」前面——链路上它在前。
2. 引入**画板（board）**作为一等实体，和建模的「设计」一一对应：一个主题的一组图 = 参考图 + **对话时间线** + 这条线上出过的每一张图（版本树）。可命名、可关联到项目、列表里有封面。
3. **「当前这张」是对话的宾语**。胶片条 / 对话里点哪张，哪张就是当前图；接下来说的「改一下」改的就是它。选一张旧图再说话 = 从那张分叉。什么都不覆盖：编辑产生新图（`parent_id` 指向被改的那张），原图留着。
4. **规划和出图是两个模型**。图片模型不会对话，也分不清「要改图」和「只是问一句」。每一轮先由 DeepSeek 的视觉模型（`deepseek-flash`，JSON 模式，提示词 `image_plan.md`）看着当前图和用户的话，一次调用决定三件事：

| 动作 | 什么时候 | 产出 |
|------|----------|------|
| `generate` | 第一次出图；「再来几张」；改动大到等于换一张；**图片模型不能编辑时的一切修改** | 一份完整的画面描述 → 文生图 |
| `edit` | 「这张基本对，只改一点」：换背景、改颜色、加 / 去掉东西 | 一条编辑指令（写明**其余保持不变**）→ 图片模型在当前图上改 |
| `reply` | 用户在提问；或要求不清楚又没有合理默认 → 反问**一个**问题 | 纯文字，不出图、不花出图的钱 |

   提示词由规划模型写，不让用户直接写：它知道这组图的**用途**（建模参考 / 场景图 / 封面 / 自由），会自动补上对应的约束（建模参考图 = 纯白底、单个物体、3/4 视角、形体清楚；封面 = 竖构图、上方留标题位……），以及 FDM 打印件的质感约束（哑光 PLA，不要镜面金属、透明玻璃）。用的提示词在每条消息里可以展开看。
5. **供应商抽象成 `ImageProvider`，核心是一个布尔值 `can_edit()`**（`crates/pp-providers/src/image.rs`）。请求里带图 = 编辑，不带 = 生成。
   - 生成用最便宜的那家，编辑用**能编辑**的那家；只配了一家就都用它；用户可以在设置里指定生成时优先用谁。
   - **一家能编辑的都没有时不假装能改**：规划模型被明确告知「不能编辑」，它会把上一张的提示词按要求改写后重新生成，并在回答里说明「这个模型不能直接改图，主体会有变化」。后端再兜一层：规划结果是 `edit` 而没有能编辑的供应商 / 没有图可改，打回重来。
6. **同一批图准备两份**：给规划模型「看」的缩到最长边 1024 的 JPEG（它只需要看清画面；原图动辄几 MB，每轮都发既慢又贵）；给图片模型「改」的**尽量是原图的字节**（每改一轮都重压一遍 JPEG 的话，图会越改越糊），超过 7 MB 才缩到 2048。一轮最多涉及 3 张图（当前图 + 新贴的）。
7. **一轮要么整轮入库，要么什么都不留**（同 ADR-0004）：规划或出图失败不写半轮消息，用户的话留在输入框里。出图成功后**立刻落盘**——供应商返回的 URL 24 小时过期。
8. 用户贴的图入库前摆正、缩到 1536、铺白底、重新编码（顺带去掉 EXIF 里的 GPS 和机型）——它会被发给第三方模型。生成的图标记 `ai_generated`，发布环节据此提醒声明 AIGC。
9. **去向**：采用（打标记）· **送去建模**（用这张图新建一个设计，它就是参考图，跳到「建模」）· 导出（文件名写 `.jpg` 而原图是 PNG 时自动转码、透明底铺白）· 从画板上拿掉（软删除，文件留在资料库）。
10. 场景图 / 封面是要发出去的：工作台上常驻一句平台规则（首图必须是实物正面图、发布要声明 AI 生成，见 04-integrations §4.3）。**不提供批量模板化换景**——那是小红书明文列出的违规示例。
11. 演示模式有一个**本机「画师」**：不联网，画一张示意图；它的「编辑」只换背景色、主体像素原样保留——正好演示「按指令改图、主体不变」是什么意思。规划那一步用内置的三条固定路线（出图 / 改图 / 回答），回答里自己写明「演示数据」。

## 接了哪两家（2026-09-20/21 按官方文档核实；**都还没有用真密钥实测过**）

| 接口 | `POST {base}/v1/image_generation` | `POST {base}/api/v1/services/aigc/multimodal-generation/generation` |
| 默认地址 | `https://api.minimax.cn` | `https://dashscope.aliyuncs.com`（百炼文档里的地址带工作空间：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com`）|
| 一次几张 | 1~9 | 1~6 |
| 返回 | base64（我们要的就是字节，不走 URL） | URL（24 h 过期）→ 立刻下载 |
| 价格（估） | ≈ ¥0.025 / 张 | ≈ ¥0.2 / 张 |
| 我们固定传的 | `aigc_watermark: false`、`prompt_optimizer: false`（提示词已经由规划模型写好，不要再被改写） | `watermark: false`、`prompt_extend: false`；**编辑时不传 `size`**（让输出跟随输入图） |

两家的**接入地址都做成了设置项**：MiniMax 有国内站 / 国际站，百炼的地址可能带工作空间。密钥和别的密钥一样，只从设置页的输入框去往系统凭据管理器。

「测试连接」对出图供应商意味着**真的出一张图**（没有免费的探活接口），设置页的说明里写明了这一点。

## 数据（schema v4）

`image_boards`（名称、项目、用途、画幅、参考图、当前图）· `image_versions`（父图、资产、提示词、generate / edit、供应商、模型、画幅、是否采用、软删除）· `image_messages`（谁说的、text / images、随类型而定的部分存一列 JSON：提示词、这一批图、改的是哪张、花费）。v2、v3 已发布，只追加不修改。

## 没有选的路

- **让用户直接写提示词**：提示词工程不是卖家该会的事；用途预设 + 规划模型写出来的提示词质量稳定得多。想看 / 想学，每条消息里都能展开。
- **火山 Seedream**：能力最强（多图参考、定位编辑），但 2026-09-21 官方文档页打不开，接口细节核实不了 → 不写没核实过的适配器。
- **通用的「OpenAI 兼容」出图适配器**（用户自己填地址和模型名）：生成这一支各家基本一致，但「编辑」各家不一样（OpenAI 是 multipart，方舟 / 硅基流动是 JSON 里带 `image`），做成通用的就得让用户理解这些差别。先把两家做扎实，列入下一步。
- **蒙版 / 框选局部重绘**：现在的编辑模型按文字指令改局部已经够用，而蒙版要一整套画布交互。等真实使用里出现「说不清楚要改哪」的情况再做。
- **抠图 + 背景生成（主体像素绝对不变）**：那是「实拍图换背景」的路线（04-integrations §4.2），属于 M2 的另一个功能，不和对话式改图混在一起。
