## 2. 预研结果

### ② 几何内核

| 通过标准 | 结果 |
|----------|------|
| 读入 → 度量 → 切平底并封口 → 导出 STL，结果仍水密 | ✅ 回归样例覆盖：立方体（侧面对角线产生**共线交点**）、球（顶点正好落在切面上）、平放环面（**带孔的环形截面**）、竖放环面（两个分离截面）、两个独立实体、切面贴着底面、切得太高、开口网格（拒绝而不是产出漏缝的结果） |
| 尺寸误差 < 0.1 mm | ✅ 体积与解析解一致（球 / 环面误差 < 1%，来自网格离散化本身；立方体精确）；STL 往返在 f32 精度内一致 |
| 真实的 AI 生成模型 ×3 | ⏳ 需要 3D 接口密钥；现在可以用「导入模型…」放进任意 STL / GLB 验证 |

关键决定：**切口封盖用约束 Delaunay 三角剖分（`spade`）而不是 earcut**。earcut 会丢掉共线点，而平直侧面被切开后轮廓上就是一串共线交点——丢点后封盖的边和侧面的边对不上，网格不再水密。CDT 保留每个轮廓顶点，内外用奇偶规则判定，带孔截面、多截面、孔里的岛都自然成立。

性能（**调试构建**，发布构建会快一个数量级）：

| 模型 | 生成 + 分析 + 落盘 | 切平底（读入 + 焊接 + 切割 + 封盖 + 分析 + 落盘） |
|------|--------------------|--------------------------------------------------|
| 球，327,680 面，15.6 MB | 4.2 s | — |
| 球，1,310,720 面，62.5 MB | 9.0 s | 8.5 s，结果 1,204,510 面，流形 |

### ④ 看图 → 代码建模（build123d）

在开发版应用里用 `scripts/cdp.py` 驱动**真实界面**走完一遍（演示模式：规格与代码是内置脚本，**代码在本机真引擎上执行**）：

|------|------|
| 引擎识别 | ✅ 面板顶部显示 `build123d 0.12.0 · Python 3.10.11`；没装时显示说明与「重新检查」 |
| 看图出规格 → 规格编辑器 | ✅ 名称、总体尺寸、3 个特征（名称 / 描述 / `名称 = 数值` 尺寸）、模型自己的假设，都可改 |

| 参数面板 | ✅ 线槽数量 3 → 5 回车：新版本入库（`slot_count: 3 → 5`），面数 38 → 50（多两道槽 × 6 面），包围盒不变，画面纹丝不动；总长 60 → 150：镜头沿原方向相应退后，零件不会撑出画面。**从回车到新版本出现 0.19 ~ 0.30 s**（冷启动时是 4.8 s） |
| 点选 + 指令修改 | ✅ 真实鼠标点在模型上 → `已选 (7.0, -8.1, 9.3)`；指令提交后新版本记着指令原文与「改动的段：demo_bottom_chamfer」，其余段逐字未动 |
| 参考图入库 | ✅ 2000 × 1200 的 PNG → 1536 × 922 的 JPEG，54 KB，EXIF 已去除 |
| 看图复核 | ✅ 同步截 4 个视角（白底带棱线，768 px，**32 ms**，不闪屏）→ 差异清单 →「按此修改」 |
| 沙箱 | ✅ `import os` 在执行前被拒：`[validate] Rejected: import os is not allowed… (line 1)`；运行时错误带用户代码的行号与那一行源码 |
| 导出 | ✅ STEP 124 KB（ISO-10303-21，能进任何 CAD）· STL 55 KB · 3MF 10 KB |
| 控制台 | ✅ 零条错误或警告 |

两条对后续有影响的发现：

- **一次引擎执行约 4 s，几乎全是冷启动**（起 Python + `import build123d`）；同一进程里连续建模只要约 50 ms。→ **已改成常驻引擎进程**：隔离措施不变，另加「任务之间不串味」的三道保险（全新命名空间、禁止给属性赋值、`math` 每任务一份替身）；应用退出时进程随 stdin 关闭自行退出（已验证无孤儿进程），遗留的沙箱目录在下次启动时清理。数字见 ADR-0003 的实测表。
- HTTP 超时从 180 s 放宽到 600 s，另加 120 s 读超时：带思考的代码生成非流式可能要几分钟；DeepSeek 在等待期间会发空行保活，所以「120 s 一个字节都没收到」才是连接坏了。

**还差的一步（需要你）**：填入 DeepSeek 密钥后，在「预研 → 代码建模」用 5~10 张真实的产品图跑一遍，记录首轮通过率、平均修复轮数、单个模型的花费与耗时（面板上每个版本都有这一行）；据此调提示词与 `max_repairs`。

|--------|------|
| 安装包 | `PrintPilot_0.1.0_x64-setup.exe` **4.3 MB**（指标是 ≤ 40 MB）；exe 9.2 MB；前端 wasm 946 KB；完整发布构建 563 秒 |
| 页面来源与 CSP | `http://tauri.localhost/`；响应头里的 `Content-Security-Policy` 已确认生效（含 `pp-asset` 的 `img-src` / `connect-src`） |
| 主界面 | 侧栏、看板、3 张项目卡片（与开发版共用同一个资料库）正常；控制台**零条**错误或 CSP 违规 |
| three.js 动态 `import()` | ✅ 在 CSP 下正常加载 |
| `pp-asset://` 取模型 | ✅ 120 万面 / 57 MB：**767 ms** 载入，**75 fps** |
| 几何性能（发布构建） | 生成 131 万面球 1.06 s；**切平底 1.41 s**（读入 62 MB + 焊接 + 切割 + 约束 Delaunay 封盖 + 分析 + 落盘），结果流形 |
| 导出 | 3MF 14.9 MB（同一模型的 STL 57.4 MB，小 3.9 倍）；耗时 3MF 5.0 s / STL 3.1 s——偏慢，见下方待优化 |

**结论：预研 ① 与 ② 通过。** three.js 视图桥这条路成立，不需要启用纯 Rust 渲染的备选方案。

待优化（不阻塞）：导出 STL 时资产本身就是 STL，应直接拷贝文件而不是「读入 → 焊接 → 重写」；3MF 的 XML 拼接可以改成流式写入。

测试留下的文件：预研过程中生成的样例模型在资料库的 `assets/lab/` 下（约 259 MB，其中大文件已在应用里软删除，但文件仍在磁盘上）；代码建模的验证又留下 4 个已软删除的版本（STEP / STL，不到 1 MB）和 1 张测试参考图。资料库位置见「设置 → 资料库」；「清理已删除资产」功能做出来之前，可以手动删掉那个 `lab` 文件夹。
