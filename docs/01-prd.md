## 1. 背景与目标

消费级 3D 打印机把「生产」变简单了，但围绕它的生意——**做什么、怎么建模、怎么上架、怎么卖得动**——仍然靠人在浏览器、出图工具、建模软件、切片软件、表格和手机 App 之间来回搬运。对单人卖家来说，瓶颈不是机器，而是**人的时间**和**试错次数**。

PrintPilot 把这条链路做成一条可度量的流水线，四个目标对应四组能力：

| 目标 | 含义 | 对应模块 |
|------|------|----------|
| **快速设计** | 从一个关键词到可打印的模型，以小时计 | M1 调研 · M2 预览图 · M3 3D 模型 |
| **快速发布** | 从实物到可发布的商品与笔记，以分钟计 | M4 成本定价 · M5 上架与发布 |
| **高效运营** | 订单不超时、内容不断更、数据不丢 | M6 运营 |
| **提高转化** | 每周知道问题在哪一环、下一步改什么 | M7 数据与复盘 |

**成功标准（自用阶段 90 天）**：想法→上架周期中位数 ≤ 3 天；单品人工耗时 ≤ 2 小时；上架 ≥ 12 个单品，其中「跑通单品」≥ 3 个。指标定义见 [05-growth-cro.md](05-growth-cro.md) §1。

### 产品形态（已定）

**Windows 桌面应用，本地优先**：一个 exe 安装包装完即用，用户机器上不需要再安装数据库、运行时或任何其他依赖；数据（数据库 + 图片 + 3D 文件）存在用户本机的「资料库」目录；AI 能力通过用户自己的接口密钥调用（BYOK）。技术选型见 [ADR-0001](adr/0001-tech-stack.md)。

### 非目标

- 不替代切片软件与 CAD（交给 Bambu Studio / OrcaSlicer / Blender / FreeCAD，平台负责顺滑交接）。
- MVP 不直接控制打印机、不做打印农场调度。
- **不做任何非官方的平台自动化**（模拟登录、爬虫、RPA 发帖、自动互动）。
- 不做云端账号、多端同步与计费（核心与界面解耦，未来可以加云服务，但不是现在）。
- 不做模型交易市场。

## 2. 市场与竞品（摘要）

完整证据与来源见 [08-market-research.md](08-market-research.md)，这里只列对产品设计有直接影响的结论：

| 发现 | 对设计的影响 |
|------|--------------|
| 需求在涨：2025 年小红书「3D 打印」搜索量同比 +238%，话题浏览超 16 亿；国内消费级市场约 200 亿元、同比 +35% | 小红书作为首发渠道成立 |
| 同质化款已是价格战：关节龙线上 9.9 元、批发 3~5 元，代打加工费跌到 0.12 元/克 | 选品评分里「差异化与定制潜力」权重要高；平台不鼓励搬运爆款，定价器显示「每机时毛利」防止陷入薄利 |
| 「AI 出图 → 图生 3D → 打印」已有卖家跑通：AI 定制 Q 版手办 19.9 元定制链接月售约 4000 单，成品 268~288 元 | 主链路可行；**个性化定制**是最强的溢价点 → 规划「定制工单」流程（P2） |
| IP 侵权是真风险：泡泡玛特、罗小黑、奥特曼版权方接连起诉，律师意见「批量打印销售即侵权」 | IP 风险在调研阶段一票否决；上架前合规 Lint 拦 IP 名词 |
| 产能极小：2 台机器满负荷日产约 4 件（手办类），拆支撑等手工占成本大头，长时间打印失败即报废 | 成本模型必须含人工与失败率；产能测算进入定价与发货时效建议 |
| 差评集中在货不对板：颜色不对、层纹、细节断层 | 商品首图强制实拍；AI 图只用于概念与氛围；详情里如实展示层纹与尺寸 |
| 新号缺自然流量，需要持续发优质内容；小红书 2026-03 起封禁「全 AI 托管」账号 | 内容日历 + 多角度草稿；**只做「AI 起草 + 人工发布」**，不做自动发帖与自动互动 |
| 竞品各管一段：海外 Printago 管「订单→排产」，Meshy / MakerLab 管「AI→模型」，国内 ERP 管「上架→订单」且对个人店过重，AI 笔记工具不懂打印 | **没有产品覆盖「选品→出图→建模→打样→上架→复盘」全流程并适配小红书个人店**——这是 PrintPilot 的位置 |

## 3. 用户与场景

**P0 用户 ·「一人工作室」**：有 1~3 台 FDM 打印机的副业卖家 / 小工作室主理人；有动手能力，但不是职业建模师，也不是职业运营；可投入时间是晚上与周末；在小红书、闲鱼等支持个人售卖的平台经营。

| 待办任务（JTBD） | 今天怎么做 | 痛点 |
|------------------|------------|------|
| 有一个空闲的晚上，想把一个想法变成能发布的商品 | 刷平台找灵感 → 找模型/自己建模 → 切片打印 → 拍照 → 写文案 → 手机发布 | 链路长、工具散，一个晚上做不完；试错次数少 → 命中率低 |
| 想知道一个点子值不值得做 | 凭感觉 | 没有证据、没有成本测算；IP 风险靠运气 |
| 订单来了，想知道先打哪个、什么时候能发 | 脑子记 / 表格 | 超时发货、漏单、定制信息对不上 |
| 卖了两周，想知道问题出在哪 | 看后台零散数字 | 数据不成漏斗，不知道该换封面还是该改价 |

**P1 用户（规模化阶段）**：2~5 人、5~20 台机器的小团队，需要多机协作与产能调度。

## 4. 核心流程与阶段门

流程图见 [02-ux-flows.md](02-ux-flows.md) §1。每个阶段用「阶段门」定义完成标准；未满足可强行推进，但必须填写原因（记入活动流，供复盘）。

| 阶段 | 进入条件 | 必备产出 | 通过标准 | 淘汰 / 回退 | 目标耗时 |
|------|----------|----------|----------|-------------|----------|
| 调研 | 关键词 / 场景 / 竞品链接 | 选品报告 + ≥1 张机会卡 | 总分 ≥ 3.5 且 IP 风险非「高」 | 总分 < 3 或 IP 高 → 淘汰 | ≤ 30 分钟（人工 ≤ 10） |
| 概念 | 已采用机会 | 1 张建模参考图 + ≥2 张场景图 | 人工确认；（可选）测款达标 | 测款不达标 → 换概念 / 淘汰 | ≤ 1 小时（测款另计 72h） |
| 建模 | 已采用参考图，或自有模型 | 通过可打印性清单的 STL/3MF | 自动检查全过 + 人工项确认 | 连续 3 次生成不可用 → 换路线（参数化 / 手工 / 外包）或淘汰 | ≤ 2 小时 |
| 打样 | 可打印文件 | ≥1 次成功打印记录 + ≥5 张实拍 + 成本模型 | 目标价下毛利率 ≥ 50% 且每机时毛利达标 | 成本不成立 → 改设计 / 淘汰 | ≤ 1 天（含打印） |
| 上架 | 实拍 + 成本模型 | 商品草稿 + ≥2 篇笔记草稿 + 合规检查 + 发布包 | 已发布并回填链接 | — | ≤ 1 小时 |
| 运营 | 已发布 | 按节奏的指标快照；订单准时发货 | 持续 | — | 每天 5 分钟 |
| 复盘 | 上架满 14 / 30 天 | 结论（放大 / 迭代 / 淘汰）+ ≥1 条经验 | — | — | 30 分钟 |

## 5. 功能需求

优先级：**P0** = MVP-α（想法→发布包）· **P1** = MVP-β（数据回流与订单）· **P2** = V1（效率与自动化）· **P3** = V2（规模化）。

### M0 · 工作台与项目看板

> 目标：一眼看到每个单品卡在哪、今天该做什么。

| 优先级 | 功能 |
|--------|------|
| P0 | 项目增删改查、自动编号（PP-0001）；阶段看板（拖拽）与列表视图；阶段门清单；活动流；暂停 / 淘汰（必填原因） |
| P0 | 任务中心：进行中 / 失败的 AI 任务，支持取消与重试，显示费用 |
| P1 | 工作台待办聚合：待采用的 AI 产出、到期的录数提醒、待发货订单、打印队列；北极星与漏斗速览；本月 AI 预算消耗 |
| P2 | 从「跑通单品」复制为模板项目（沿用提示词与参数） |

**验收**：新建项目 ≤ 10 秒；卡片显示本阶段关键数与「已停留 N 天」，超阈值高亮；强行推进会弹出原因输入并写入活动流。

### M1 · 市场调研 Agent

> 目标：把「凭感觉选品」变成「带证据的机会评分」，单次 ≤ 5 分钟、≤ ¥1。

**用户故事**
- 作为卖家，我输入「桌面收纳」和我的打印机/价位约束，得到 3~5 个具体的产品机会，每个都有评分、依据和风险，我可以一键把其中一个变成项目。
- 作为卖家，我可以把自己看到的竞品链接或截图交给它，让结论建立在我的一手观察上。

| 优先级 | 功能 |
|--------|------|
| P0 | 调研任务：输入（关键词/场景 + 约束）→ 规划 → 联网检索 → 阅读抽取 → 机会评分 → 审校 → 报告；全程进度可见 |
| P0 | 产出：带引用的报告、机会卡片、证据卡（URL · 摘录 · 日期 · 证据等级 A/B/C）；「推测」类结论显式标注 |
| P0 | 「采用为项目」：自动填入定位、人群、卖点、价格带、量级估算（尺寸/克数/时长） |
| P0 | 用户补充证据（粘贴链接 / 文本）；单次预算上限与费用显示；同输入 24 小时内命中缓存 |
| P1 | 上传截图作为证据（视觉模型解析）；对报告追问（有界对话） |
| P2 | 趋势雷达：订阅关键词，每周扫描并把新机会放进灵感池；经验库自动注入评分上下文 |
| P2 | 竞品跟踪：登记竞品，定期录入价格/销量变化 |

**验收**：报告内每个数字型结论要么带引用、要么标「推测」；每张机会卡字段完整（一句话定位 / 目标人群 / 3 个卖点 / 价格带 / 七维评分与依据 / 风险 / 打印量级估算）；IP 风险为「高」的机会不能直接采用，需二次确认。

**设计要点**：采用有界流水线而非开放式 Agent 循环（见 [03-architecture.md](03-architecture.md) §7）。纯 LLM 的「市场调研」容易一本正经地编数字，所以产品上强制「证据卡」与「证据等级」，并鼓励用户喂一手观察。

### M2 · 产品预览图

> 目标：10 分钟内得到「能拿去建模的图」和「能拿去测款的图」。

三种用途、三套策略：

| 用途 | 追求 | 典型参数 |
|------|------|----------|
| **建模参考图** | 几何清晰：白底、单一物体、3/4 视角、无遮挡、无透明镂空 | 1:1，n=4 |
| **场景效果图** | 氛围与使用场景：用于测款与种草 | 3:4，n=4 |
| **笔记封面** | 可读性：实拍/效果图 + 模板叠字（文字由模板渲染，不交给 AI 画） | 3:4 |

| 优先级 | 功能 |
|--------|------|
| P0 | 由概念简述起草提示词（可编辑）；风格/配色/比例/数量；批量生成；采用与版本；全部图片落本地存储 |
| P0 | 图生 3D 友好度自检清单（MVP 人工勾选）；「送去建模」 |
| P0 | AI 生成图打标（`ai_generated`），导出时可叠加显式标识 |
| P1 | 封面模板叠字并导出 3:4（1080×1440）；实拍图管理（上传 / 裁剪 / 排序） |
| P1 | 实拍图换背景（抠图 + 背景生成，**主体像素不变**），生成后与原图并排供人工比对 |
| P1 | 友好度自检自动化（视觉模型） |
| P2 | 配色变体图；风格预设库；品牌视觉一致性 |

**验收**：点击生成到 4 张图可见 ≤ 60 秒（供应商正常时）；失败自动重试 1 次；不依赖供应商的临时 URL（普遍 24 小时过期，生成后立即落盘）。

**产品红线**（来自小红书规则，见 [04-integrations.md](04-integrations.md) §4.3）：

- 商品**首图必须是正面实拍**，不得拼接、不得带文字水印——上架检查会拦截把 AI 图设为首图的操作。
- 平台已把「用 AI 批量更换场景、主体等模板化操作」列为违规示例 → 换背景功能**不提供批量模板化换景**，只用于笔记配图与主图的非首图。
- AI 图的定位是概念测款、场景氛围与封面底图；所有 AI 生成图打标，发布清单提醒勾选平台的 AI 内容声明（未声明会被平台自动打标并限流）。

### M3 · 3D 模型生成 / 预览 / 编辑

> 目标：得到一个「切片软件里直接能切」的文件，而不是一个「看起来不错」的模型。

**入口与交互**（[ADR-0004](adr/0004-modeling-studio.md)）：建模是侧栏的**一级入口「建模」**，不挂在预研或某个项目页下面。核心概念是**设计**——一个零件的一条建模线索：参考图 + 设计规格 + **和 AI 的持续对话** + 版本树；可命名、可关联到项目。对话是主线：第一句话（可带图）出规格，确认后生成；之后每句话 AI 自己判断是改模型、回答问题还是反问澄清；改参数、手改代码、看图复核都记在同一条时间线上。

**三条建模路线，分析之后合流**（主路线的决策见 [ADR-0003](adr/0003-code-cad-build123d.md)）：

| 路线 | 适合 | 阶段 |
|------|------|------|
| **看图 → 代码建模（build123d，主路线）** | 能用「草图 + 拉伸 / 旋转 + 布尔 + 圆角」描述的：收纳、支架、夹具、外壳、铭牌、几何风摆件。产物是参数化的 B-rep（STEP），尺寸精确、可局部修改 | **P0** |
| 导入自有模型（STL / 3MF / OBJ / GLB） | 已有 CAD 设计（如 FreeCAD 导出）、购买了商用授权的模型 | P0 |
| AI 网格生成（图生 3D / 文生 3D） | 有机、装饰造型：摆件、潮玩、花器。看图出规格时判定「不适合代码建模」的造型走这条 | P1（原 P0，让位于主路线） |

| 优先级 | 功能 |
|--------|------|
| P0 | **看图出规格**：产品预览图 / 照片（最多 4 张）+ 文字要求 → 设计规格（总体尺寸、特征清单、关键尺寸、模型自己的假设）。**规格先给人审、给人改，确认了才生成**；有机造型如实判为「不适合」 |
| P0 | **生成**：按规格写 build123d 脚本 → 本机引擎执行 → 自动检查（1 个实体、几何有效、贴床、尺寸与规格相符、放得进成型空间）→ 不合格把原因喂回去修（有上限）。修不好也交付「问题最少的一版」并列出遗留问题 |
| P0 | **对话式修改（持续对话）**：AI 记得上下文（「再宽一点」「改回去换成 U 形底」）；一句话可以带**在模型上点选的位置**和**新贴的图**；AI 自己判断是改模型、回答（「要加支撑吗」）还是反问澄清；改模型时只动相关特征段，改了哪些段、自动修了几轮都显示在这条消息上；**每次修改可一键撤销**，选中旧版本再说话 = 从那一版分叉；没改成时如实给出最后一版代码和引擎的真实报错 |
| P0 | **微调**：参数面板——改数字即重建（约 0.2 秒），不经过模型、不花钱；手动改动也进时间线，AI 下一句话知道你改过什么 |
| P0 | 设计管理：列表（缩略图、尺寸、版本数）、重命名、关联项目、删除；模型档位（快 / 均衡 / 精细）由用户按「这一句值不值得等」自己选 |
| P0 | **看图复核**：4 个视角的渲染图 vs 参考图 → 差异清单，每条差异一键交给指令修改 |
| P0 | 版本树（生成 / 参数 / 修补 / 手写，父子关系、可回退）；代码可见、可手改、可直接运行；导出 STEP / STL / 3MF |
| P1 | 图生 3D 网格任务（提交 / 进度 / 失败重试）；结果落盘 |
| P0 | 预览：轨道控制、实体/线框、尺寸标注（mm）、打印机成型范围参考框 |
| P0 | 模型度量：包围盒、体积、面数、水密/流形检查 |
| P0 | 轻编辑：缩放到目标尺寸、摆正贴床、切平底、镜像；导出 STL（及 3MF） |
| P0 | 可打印性清单（自动项 + 人工确认项），通过后才能进入打样 |
| P1 | 一键在切片软件中打开；体积法估算克数与时长，写入成本模型 |
| P2 | 一键修复非流形；减面；文字浮雕/刻字；参数化模板 + 订单定制字段自动出打印文件；切片 CLI 精确估算；悬垂/壁厚热力图 |
| P3 | 多色分件（AMS）；同图多供应商对比生成；打印机状态集成 |

**验收（代码建模）**：演示脚本在真引擎上过完整流水线（含一轮真实报错的自动修复）；改一个参数只改变对应尺寸、面数不变；指令修改后 `changed_sections` 只含相关的段；生成的代码碰不到文件系统与网络（白名单 + 子进程隔离）。真模型下的首轮通过率、平均修复轮数、单模型成本待实测后定指标。

**验收（预览与网格）**：50 万面以内模型在主流笔记本浏览器中交互 ≥ 30 fps；导出的 STL 在 Bambu Studio / OrcaSlicer 中可直接切片，尺寸误差 < 0.1 mm；切平底后模型仍为水密流形。

**设计要点**：个人卖家能稳定做出来、做得好卖的，绝大多数是规则几何的功能件与几何风装饰件——正好是代码式 CAD 的强项：尺寸精确、参数化（一个脚本出一个尺寸系列、刻字定制）、单个成本约 ¥0.1、改参数不花钱。AI 网格生成留给有机造型。平台在调研阶段的「可打印性」评分里就会给出路线建议（`route`）。

### M4 · 打样与成本定价

> 目标：每个单品上架前就知道「卖多少钱、赚多少、一天最多接多少单」。

| 优先级 | 功能 |
|--------|------|
| P0 | 打印机档案（成型尺寸、功率、购入价、预期寿命）与耗材档案（类型、颜色、元/公斤、库存） |
| P0 | 打印记录：预估 vs. 实际（时长、克数）、成功/失败与原因、照片 |
| P0 | 成本模型 + 三档建议售价 + 每机时毛利；与调研得到的竞品价格带并排 |
| P0 | 渠道费率预设（可改）：小红书模玩 / 家居饰品 / 文创手作 5%、个性定制 / DIY 2%；闲鱼 0.6%；微信小店 1%~5% |
| P1 | 产能测算 → 日接单上限 → **建议「现货」还是「预售 N 天」**（小红书现货须 48 小时内发货；个人店预售天数上限随店铺分为 7 / 15 / 30 天）；耗材库存扣减与低库存提醒 |
| P2 | 检测到本机切片软件时用其命令行做精确估算；失败原因统计 → 改进建议 |

```
材料成本   = 克数 × (1 + 损耗率) × 耗材单价 ÷ 一次成功率
机时成本   = 打印小时 × (功率kW × 电价 + 机器购入价 ÷ 预期寿命小时)
人工成本   = (后处理 + 打包 分钟) × 人工分钟单价
单位成本   = 材料 + 机时 + 人工 + 包装 + 运费补贴
建议售价   = 单位成本 ÷ (1 − 平台费率 − 目标毛利率)      → 再取尾数价
每机时毛利 = (售价 × (1 − 平台费率) − 单位成本) ÷ 打印小时
```

**验收**：改任一参数，售价与毛利即时重算；成本模型可一键引用最近一次成功打印的实际值。

### M5 · 上架与发布

> 目标：从实物到「手机上点发布」≤ 1 小时，其中从扫码到发布完成 ≤ 2 分钟。

| 优先级 | 功能 |
|--------|------|
| P0 | 商品草稿：标题、卖点、详情、SKU、价格（引用成本模型） |
| P0 | 笔记草稿：按角度生成（痛点 / 场景 / 过程 / 设计幕后 / 定制故事），≥2 个候选；话题建议；品牌语气 |
| P0 | 渠道规格校验（字数、图片比例与数量）+ 合规 Lint（极限词、功效宣称、IP 名词、AI 内容声明提醒） |
| P0 | **发布包**：处理好的图片 + 文案。方式 A 在电脑上发布（打开素材文件夹 + 打开渠道官方网页版发布入口 + 逐项复制）；方式 B 手机扫码页（保存图片 / 一键复制标题、正文、话题）。回填链接后状态变为「已发布」 |
| P1 | 封面变体并关联实验；内容日历（计划、提醒——**只提醒，不代发**）；闲鱼文案风格适配与经营性阈值计数提醒 |
| P2 | **微信小店 API 渠道**（面向已办个体工商户执照的用户）：商品推送、订单同步、发货回传 |
| P3 | 小红书官方 API（只能以企业服务商身份获得，远期评估） |

**验收**：未通过校验不能生成发布包（可强制跳过，记录原因）；发布包手机页四个主按钮首屏可见；从点开发布包到发布完成 ≤ 2 分钟；回填链接后项目自动进入「运营」。

**设计要点**：调研确认小红书**没有笔记发布 API**，电商开放平台也明文排除个人店与个体工商户；2026-03 起平台封禁通过托管工具发布、互动的账号，连「脚本操作网页版定时发布」都有被封案例。所以**半自动发布不是权宜之计，而是这个产品的正式形态**：AI 负责起草与打包，人负责点「发布」。渠道通过「能力声明」接入（见 [03-architecture.md](03-architecture.md) §5），将来哪个渠道开放了接口，界面自动升级为直连。

### M6 · 运营

> 目标：不漏单、不超时、不断更。

| 优先级 | 功能 |
|--------|------|
| P1 | 订单导入（官方后台导出文件 / 手工录入），关联单品、SKU 与定制信息 |
| P1 | 打印队列：待打印 → 打印中 → 后处理 → 已打包 → 已发货；按发货截止时间排序；超时风险高亮；发货登记 |
| P1 | 录数提醒（T+1 / T+3 / T+7 / T+30）+ 截图识别录入 |
| P1 | 发货时效预警：现货 48 小时、预售按设定天数；预售超期率接近 10% 红线时告警 |
| P2 | 客服回复建议（基于商品 FAQ，**不含买家个人信息**）；同材料同色合盘建议；热销单品安全库存建议 |
| P2 | **定制工单**：买家需求 / 照片 → 预览图确认 → 建模 → 打印（复用 M2 / M3）。买家照片属个人信息：调用第三方接口前需确认已获买家同意，完成后按设置自动清除原图 |
| P3 | 订单 API 同步（随微信小店渠道）；打印机状态集成；产能外包（在线代工询价） |

**验收**：导入 50 单 ≤ 1 分钟；队列视图能直接回答「现在该打哪个」「哪一单有超时风险」。

### M7 · 数据与复盘

> 目标：每周 30 分钟，得到「下周只做这 1~2 件事」的结论。

| 优先级 | 功能 |
|--------|------|
| P1 | 指标快照（API / CSV / 截图 / 手填 四种来源同表）；单品漏斗；与自己的基线对比 |
| P1 | 周报 Agent：按诊断规则定位问题环节，给出按 ICE 排序的实验建议 |
| P2 | 实验管理（假设 / 变体 / 主指标 / 结论）；经验库；单品 P&L（含 AI 花费、材料、运费、平台费）；单品对比 |
| P3 | 跨渠道归因；销量预测与备货建议 |

**验收**：每个在售单品一屏看清漏斗与 P&L；周报每条建议都能回指到具体数据。

### M8 · 设置

| 优先级 | 功能 |
|--------|------|
| P0 | 接口密钥：三种预设（性价比组合 / 一家搞定 / 自定义），每把密钥「测试连接」，密钥只存系统凭据管理器；**演示模式**（不配密钥也能用内置样例走完整条流水线） |
| P0 | 资料库位置（可放非系统盘、可迁移）；打印机与耗材；成本参数；三级预算闸门（单任务 / 单项目 / 月度） |
| P0 | 网络代理；主题（浅色 / 深色）；检查更新 |
| P1 | 渠道配置与能力声明；品牌语气；违禁词库；一键备份 / 恢复资料库 |
| P2 | 界面英文；问题反馈包（日志 + 环境信息，脱敏） |

**设计要点**：BYOK 意味着用户要自己去几家平台注册、充值、拿密钥——这是外部用户**最大的上手障碍**。对策是预设方案 + 逐步引导 + 能力降级（没配的能力给明确提示而不是报错）+ 演示模式；长期可以提供官方中转额度，但那会带来生成式 AI 服务的合规义务（见 [07-risks-compliance.md](07-risks-compliance.md)）。

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| 安装与分发 | **一个 exe 安装包，零外部依赖**（不装数据库、运行时、VC++ 运行库）；Windows 10 / 11 x64；免管理员权限安装；安装包 ≤ 40 MB；代码签名；应用内自动更新 |
| 本地优先 | 数据全部在用户本机的资料库目录；除 AI 生成外的功能离线可用；资料库可迁移、可一键备份 |
| 性能 | 冷启动到可操作 < 3 秒；3D 视口 50 万面 ≥ 30 fps；3D 库懒加载，不拖慢主界面 |
| 可靠性 | 任务可重试、可取消；应用重启后任务接着跑、不重复扣费；第三方结果 100% 落盘 |
| 成本 | 每个想法的 AI 花费默认 ≤ ¥10；超限拦截并提示 |
| 隐私 | 买家个人信息最小化、加密、到期脱敏；不进入 LLM 上下文 |
| 合规 | AIGC 标识；渠道红线；上架前合规 Lint。详见 [07-risks-compliance.md](07-risks-compliance.md) |
| 可维护 | 供应商 mock 模式；适配器契约测试；提示词回归样例 |
| 国际化 | 中文优先；文案与渠道规格抽离，为海外渠道预留 |

## 8. 埋点与度量（平台自身）

这些事件**只记在用户本机的数据库里**，用来算工作台上的速度与质量指标；不上传，遥测默认关闭。

| 事件 | 用途 |
|------|------|
| `stage_changed(project, from, to, forced, reason)` | 阶段耗时、周期、强推比例 |
| `job_finished(type, provider, status, duration, cost)` | 成功率、时延、成本 |
| `asset_adopted(kind, role, candidates)` | 采用率（提示词与供应商质量的代理指标） |
| `publish_pack_opened / link_backfilled(duration)` | 半自动发布耗时 |
| `snapshot_recorded(source, edited_fields)` | 截图识别准确率（人工修改了几个字段） |
| `review_decision(project, decision)` | 命中率、淘汰原因分布 |
